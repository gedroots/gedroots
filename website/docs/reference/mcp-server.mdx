GEDRoots serves the [Model Context Protocol](https://modelcontextprotocol.io) so that an AI agent can read the open tree and propose records. To set it up and review proposals, see [Research with an AI agent](/workflows/ai-agents).

## Connection

| | |
| --- | --- |
| Turn on | **GEDRoots › Connect an AI Agent…**, **Allow AI agents**, then pick your agent for its setup |
| Address | `http://127.0.0.1:47280/mcp` |
| Transport | Streamable HTTP |
| Authentication | `Authorization: Bearer <token>` header. The connection window shows it, masked, with a button to copy it. |
| Runs | While GEDRoots is open and the setting is on |
| Trees | Every tree open in GEDRoots. Tools work on the window in front, unless given `tree` (a name, file name or id from `list_trees`) |

The server refuses requests sent by a web page (with an `Origin` header). The setting and the token are stored in `GEDRoots/agents` in your system's configuration folder: `~/Library/Application Support` on macOS, `~/.config` on Linux, `%APPDATA%` on Windows.

## Tools

The tools return structured JSON. None changes your tree's data: `propose_act`, `propose_change`, `propose_chapter` and `withdraw_proposal` only add or take back a proposal to review, and `plan_research` and `log_search` only write the research log, with an undo step.

| Tool | Returns |
| --- | --- |
| `list_trees` | The trees open in GEDRoots, the one in front first: name, file, number of people, families, sources and media, root person |
| `file_context` | How the file is written: the description you wrote in **File Settings › General**, its language and place format, the events, custom event types and occupations in use, where media are filed, and the latest records changed |
| `search_people` | People matching a search, with the syntax of the app's [search field](/reference/search-criteria) |
| `person_sheet` | A person's events with date, place, street address, age, cause, cited sources, media, witnesses and notes; parents, unions, children; Sosa number |
| `research_leads` | The records still to find for the people of a focus (by default the root person's ancestors over 6 generations): births, marriages and deaths missing or without a source, and the parents of ancestors at the end of a line, each with its estimated years, places and where to look |
| `research_log` | What was planned and searched for a person and their unions |
| `plan_research`, `log_search` | Note the agent's plan, then each search it makes, whatever its result, in the research log |
| `quality_issues` | The Data Quality page's issues, filtered by category, kind or record: message, records and places involved, whether the page fixes it in one click, whether it can be hidden |
| `search_sources` | Sources (register, repository, call number, number of records) and repositories, to cite an existing one |
| `match_people` | For the people named in a record, the people of the tree who could be them, with the reason and whether the match is likely |
| `locate_place` | For one place of a record, the tree's places of that name and the gazetteer's candidates, each with its distance to the places where the record's people lived |
| `propose_act` | Adds a record to the To Review page: event, date, place, source, reference, transcription, people with their role and who they are (linked, created or only mentioned), the other facts the record gives, downloaded file, address of the record's page. With `replaces`, it corrects a waiting proposal |
| `list_proposals`, `withdraw_proposal` | The proposals waiting for review and what became of the others; take one back |
| `propose_change` | Adds a change to the To Review page: the Data Quality page's own fix, an edit, merging a possible duplicate or hiding a correct issue, or, without an issue, a correction read in a document (a name, a date, a sex) |
| `read_book`, `propose_chapter` | The family books and their chapters; what the agent wrote for one chapter (narratives, historical context with its sources, hypotheses), reviewed in To Review |

Identifiers such as `I12` are only for passing between tools. The server's instructions ask the agent not to show them to you.

## Prompts

| Prompt | Arguments | Does |
| --- | --- | --- |
| `research_session` | `focus`, `count`, both optional | Reads the leads, saves a plan, searches each lead, notes every search, proposes the records found, then sums up what to try next |
| `find_record` | `person`, `event`, both optional | Picks a lead with `research_leads`, finds the archive and register, searches it at a human pace, downloads the record and continues with `read_record` |
| `read_record` | `file`, `person`, both optional | Transcribes the record, checks it against the person's sheet, identifies each person with `match_people`, picks or describes the source with `search_sources`, then calls `propose_act` and corrects the proposal if it's refused |
| `review_quality` | `category`, `person`, both optional | Goes through the Data Quality issues, checks each one against the sheets and sources, and proposes a fix, an edit or hiding it with `propose_change` |
| `write_book` | `book`, `chapter`, both optional | Writes a family book chapter by chapter, with historical context searched in reliable sources, and proposes it with `propose_chapter` |

In Claude Code, prompts appear as commands, such as `/mcp__gedroots__research_session`.

## Validation of proposals

`propose_act` uses the same model as the [record editor](/workflows/records). A proposal is refused, with the reason, when:

- the source or repository doesn't exist, and the new source doesn't name its register;
- it gives a person a parent other than the one already in the tree;
- a person to create resembles someone of the tree (same names, or a relative of a linked person, with compatible dates) that the agent neither linked nor ruled out. The refusal lists the candidates;
- a linked person doesn't exist;
- a date is invalid. Valid dates are rewritten in GEDCOM 7 syntax.

How the file writes its records (one source per record or per register, titles) isn't checked: the agent learns it from `file_context`, and you review each proposal.

A proposal is checked against your tree as if the proposals already waiting were saved. A person created by a waiting proposal has a temporary id, such as `new-3`: the agent links it to name the same person in another record, and creating them a second time is refused. Whichever of those records you save first creates the person, and the others link to them.

Each answer of a tool also tells the agent what you did with its proposals since its last call (`news`): saved, with the identifiers the new people now have in your tree, rejected, or opened in the record editor.

A place named like a place of the tree becomes that place. A PDF register page is extracted as a JPEG image when the file's other records are images. The address of the record's page in the archive's viewer becomes a web link of the source.
