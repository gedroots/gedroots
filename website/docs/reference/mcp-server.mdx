GEDRoots serves the [Model Context Protocol](https://modelcontextprotocol.io) so that an AI agent can read the open tree and propose records. To set it up and review proposals, see [Research with an AI agent](/workflows/ai-agents).

## Connection

| | |
| --- | --- |
| Turn on | **File › Connect an AI Agent…**, **Allow AI agents**, then pick your agent for its setup |
| Address | `http://127.0.0.1:47280/mcp` |
| Transport | Streamable HTTP |
| Authentication | `Authorization: Bearer <token>` header. The connection window shows it, masked, with a button to copy it. |
| Runs | While GEDRoots is open and the setting is on |
| File | The file of the most recently active GEDRoots window |

The server refuses requests sent by a web page (with an `Origin` header). The setting and the token are stored in `GEDRoots/agents` in your system's configuration folder: `~/Library/Application Support` on macOS, `~/.config` on Linux, `%APPDATA%` on Windows.

## Tools

The tools return structured JSON. All are read-only, including `propose_act` and `propose_change`, which only add a proposal to review.

| Tool | Returns |
| --- | --- |
| `file_info` | File name, counts, root person |
| `search_people` | People matching a search, with the syntax of the app's [search field](/reference/search-criteria) |
| `person_sheet` | A person's events with date, place, cited sources and media; parents, unions, children; Sosa number |
| `research_gaps` | Births, marriages and deaths missing or unsourced among the root person's direct ancestors, by Sosa number, with each person's known places |
| `quality_issues` | The Data Quality page's issues, filtered by category, kind or record and paged: message, records and places involved, whether the page fixes it in one click, whether it can be hidden, counts per category |
| `search_sources` | Sources (register, repository, call number, number of records) and repositories, to cite an existing one |
| `match_people` | For the people named in a record (role, names, sex, age, record date), the people of the tree who could be them, with the reason and whether the match is likely |
| `propose_act` | Adds a record to the To Review page: event, date, place, source, reference, transcription, people with their role and who they are (linked, created or only mentioned), the other facts the record gives about each person, downloaded file, address of the record's page. The answer lists everything that will be written (`will_write`) |
| `propose_change` | Adds a change for one Data Quality issue to the To Review page: the page's own fix, edits the issue allows, or hiding an issue that is correct, with the reason and the evidence. The change is checked on a copy first: it is refused if the issue would remain, and the answer lists the issues it would create |

Identifiers such as `I12` are only for passing between tools. The server's instructions ask the agent not to show them to you.

## Prompts

| Prompt | Arguments | Does |
| --- | --- | --- |
| `find_record` | `person`, `event`, both optional | Picks a gap with `research_gaps`, finds the archive and register, searches it at a human pace, downloads the record and continues with `read_record` |
| `read_record` | `file`, `person`, both optional | Transcribes the record, checks it against the person's sheet, identifies each person with `match_people`, picks or describes the source with `search_sources`, then calls `propose_act` and corrects the proposal if it's refused |
| `review_quality` | `category`, `person`, both optional | Goes through the Data Quality issues, checks each one against the sheets and sources, and proposes a fix, an edit or hiding it with `propose_change` |

In Claude Code, prompts appear as commands: `/mcp__gedroots__find_record`, `/mcp__gedroots__read_record` and `/mcp__gedroots__review_quality`.

## Validation of proposals

`propose_act` uses the same model as the [record editor](/workflows/records). A proposal is refused, with the reason, when:

- the source or repository doesn't exist, and the new source doesn't name its register;
- it doesn't follow the file's habit for that register: one source per record, or one per register with the record's reference;
- it gives a person a parent other than the one already in the tree;
- a person to create resembles someone of the tree (same names, or a relative of a linked person, with compatible dates) that the agent neither linked nor ruled out. The refusal lists the candidates;
- a linked person doesn't exist;
- a date is invalid. Valid dates are rewritten in GEDCOM 7 syntax.

A place named like a place of the tree becomes that place. A PDF register page is extracted as a JPEG image when the file's other records are images. The address of the record's page in the archive's viewer becomes a web link of the source.

## Living people

A person with no death, burial or cremation is treated as living, unless their birth, or a date that places it, is more than 100 years ago. The agent can find and link a living person, but only gets what identifies them: their name, their birth (date and place) and their close relatives. Their other events and notes are left out of their sheet, and they are not among the research gaps.
