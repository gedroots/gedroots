# GEDRoots documentation

The user documentation of GEDRoots, built with [Blume](https://useblume.dev). Pages are in
`docs/`, one MDX file per page; folders are sidebar groups, ordered by their `meta.ts`.

```sh
cd website
bun install        # or: npm install
bun run dev        # live preview on http://localhost:4321
bun run build      # static site in dist/
bun run check      # broken links and anchors
```

## Writing guidelines

The documentation follows [Diátaxis](https://diataxis.fr) and the
[Google developer documentation style guide](https://developers.google.com/style):

- **Get started** is a tutorial: one path, from installation to a first sourced record.
- **Workflows** are how-to guides, named after a genealogy task (“Record what a source
  says”), not after a screen. Each opens with what the reader will achieve, then numbered
  steps.
- **Concepts** explain why GEDRoots works the way it does.
- **Reference** is exhaustive and dry: shortcuts, criteria, checks, extensions.

Style: second person, present tense, active voice, sentence-case headings. UI labels in bold,
exactly as in `crates/gedroots/locales/*.yml` (`en`); menu paths as **File › Export**.
Shortcuts give macOS first, then Windows and Linux: <kbd>⌘E</kbd> / <kbd>Ctrl+E</kbd>.
GEDCOM tags and values in code font. No GEDCOM identifiers in examples except in reference
pages.

## Screenshots

Screenshots use a fictional family generated by `scripts/demo_tree.py`, never a real tree:

```sh
python3 website/scripts/demo_tree.py /tmp/demo   # writes demo.ged and its record images
GEDROOTS_LANG=en mise run app /tmp/demo/demo.ged
```

Take them in English, at a window size of 1600 × 1000, and save them in `docs/images/`.
